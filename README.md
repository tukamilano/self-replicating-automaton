# フォン・ノイマンの自己複製オートマトンを動かす

フォン・ノイマンの自己複製の論理を、**抽象論理 → 29状態セルオートマトン → 本物の自己複製機**
の3段階で実際に動かすためのコードです。

```sh
pip install -e '.[dev]'          # numpy, matplotlib, pytest
./scripts/fetch_patterns.sh      # 段階3用: Golly 同梱の JvN29 パターンを取得
pytest                           # 全テスト
```

## 段階1: 抽象論理 — `vn/logic/machine.py`

```sh
python vn/demos/01_logic.py
```

| 記号 | 役割 |
|---|---|
| **A** 万能構成機 | 記述 φ(X) を読んで機械 X を作る |
| **B** 複製機 | φ を解釈せずにそのまま写す |
| **C** 制御機 | A → B → 「子に写しのテープを付ける」の順に起動する |
| **φ** 記述テープ | 部品1個 = 4ビットの符号語 |

A+B+C に φ(A+B+C) を持たせると、子は親と同一になります。ポイントは
**φ が φ 自身を含まない**こと。テープは B が写すだけなので、自己言及の無限後退が起きません。
デモでは次を確かめます:

1. A+B+C+φ(A+B+C) の子が親と同一、個体数は倍々
2. B が無いと子はテープを持たず増えない／φ に φ 自身を入れようとすると記述長が発散する
3. 付加機 D も遺伝する
4. φ の1ビット変異が遺伝する（体に現れるのは次の世代から = 遺伝子型と表現型）
5. A を壊す致死変異は広がらない

## 段階2: 29状態セルオートマトン — `vn/ca/`

| ファイル | 内容 |
|---|---|
| `states.py` | 29状態（Golly の JvN29 と同じ番号） |
| `rules.py` | 遷移規則。`signal_from`（隣から届く入力）と `next_state`（入力から次状態）の2段 |
| `grid.py` | 格子エンジン。規則を表にして numpy で一括適用。前ステップで変わったセルの近くだけ再計算する（厳密） |
| `construct.py` | 構築符号（9種）、ビット列を注入する `Feeder`、ASCII レイアウト |
| `render.py` | ターミナル表示 / matplotlib 画像・GIF |
| `rle.py` | Golly の RLE 形式の読み書き |

規則の正しさは、Golly のソース (`gollybase/jvnalgo.cpp`) をそのまま訳したオラクル
`tests/golly_ref.py` と照合しています（全状態 × 隣2方向の全組合せ ＋ ランダム30万近傍、
格子エンジンも全面計算と40世代照合）。

```sh
python vn/demos/02_signal.py                 # 分岐 / AND / 破壊と自己修復 / 発振器
python vn/demos/03_construct_arm.py          # 9種の構築符号 / テープからループを建てる
python vn/demos/02_signal.py --gif out/signal.gif   # GIF で保存 (--mpl でウィンドウ表示)
```

構築の符号（U に入る信号列）:

| 符号 | 状態 | 符号 | 状態 | 符号 | 状態 |
|---|---|---|---|---|---|
| 10000 | 通常 → | 1011 | 特殊 ⇒ | 1111 | 合流 C |
| 10001 | 通常 ↑ | 1100 | 特殊 ⇑ | | |
| 1001 | 通常 ← | 1101 | 特殊 ⇐ | | |
| 1010 | 通常 ↓ | 1110 | 特殊 ⇓ | | |

ここでは φ を読み取る装置は Python の `Feeder` が代役をしています。φ を読む装置まで
セル空間の中に作ったものが、段階3の本物の自己複製機です。

## 段階3: 本物の自己複製機 — `vn/demos/04_load_replicator.py`

Golly 同梱の `small-JvN-self-replicator.rle`（Redstoneboi, 2018。JvN29 規則、12314×21 セル、
周期 221,693 世代）を自作エンジンで動かします。

```sh
python vn/demos/04_load_replicator.py --watch       # 機械部分の動きをターミナルで観察
python vn/demos/04_load_replicator.py               # 1周期完走 → 親と同一の子を検出
```

下端2行がテープ φ（構築命令が周回する長い信号ループ）、左端が制御部です。
`--watch` で見ると、制御部から特殊伝達2本組の構築アーム（⇑⇓）が上へ伸びていくのが分かります。

完走後、格子全体から元のパターンと**構造**（セルの種類と向き）が一致する個体を探し、
**信号**（励起・合流の位相）の違いと分けて報告します。実測結果（このマシンで約10分）:

```
世代 221693 で元のパターンと構造が一致する個体: 2 個
  子: 左上 (行 -18, 列 23)  占有 24866 セル中 構造の違い 0 / 信号の位相の違い 34
  親 (元の位置): 左上 (行 0, 列 0)  占有 24866 セル中 構造の違い 3 / 信号の位相の違い 8494
```

- 子は元のパターンと構造が完全に同じで、テープの信号の位相まで一致しています。
  違う34セルは子の制御回路を流れているパルスで、子がもう起動して次の複製を始めていることを示します。
  （ほかに、親とつながる継ぎ目のセルが1つ余分にあります。）
- 親の構造の違い3セルは、起動用の回路を親自身が消したものです。
- 500世代後には両方のテープが回っていて、信号の違いは約1.2万セルになります。
  つまり公称周期 221,693 世代ちょうどで子が元のパターンと同じ位相になる、ということも確認できます。

スナップショット画像（全体の縮小図と機械部分の拡大図）は `out/replicator/` に保存されます。

## 実装しなかったこと

- 構築アームの後退（特殊伝達でアーム先端を壊しながら戻る操作）は、段階2のデモでは扱っていません。
  段階3の複製機の中では実際に行われています。
- フォン・ノイマン原設計そのもの（数十万セル規模）や Nobili32/Hutton32 などの拡張規則は対象外です。
